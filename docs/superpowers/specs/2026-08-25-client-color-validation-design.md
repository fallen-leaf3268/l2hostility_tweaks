# 客户端颜色配置严格校验设计

## 背景

客户端 HUD 的颜色分段配置只通过正则确认字段由数字组成，没有验证 RGB 通道是否处于 `0` 到 `255`。默认颜色使用相同的不完整校验。Minecraft 的 `FastColor.ARGB32.color` 不会限制通道值，而是直接进行位移和按位合并，因此超范围值会污染相邻通道。例如 `256,0,0` 最终会打包成黑色，而不是红色。

颜色分段中的难度字段也只接受数字文本，却没有确认其能被 Java `int` 解析。超出整数范围的值可通过配置校验，随后在运行时被静默跳过。

## 目标

- 颜色分段只接受 `难度,R,G,B` 四个十进制整数字段。
- 难度必须处于 `0` 到 `2147483647`。
- 每个 RGB 通道必须处于 `0` 到 `255`。
- 默认颜色只接受三个范围有效的 RGB 字段。
- 配置声明与运行时解析复用同一套规则，避免校验和消费逻辑分叉。
- 非法颜色分段在运行时被跳过，不影响其他合法分段。
- 非法默认颜色在运行时回退为 `170,170,170`。
- 所有当前合法默认值及难度匹配排序保持不变。

## 非目标

- 不自动把超范围 RGB 钳制到边界。
- 不支持十六进制、浮点数、带符号数或其他颜色格式。
- 不改变血条渐变、宽度、位置或难度分段选择逻辑。
- 不修改服务端或通用配置。

## 设计

在 `ClientL2HConfig` 内提供包内可测试的纯解析方法：

- 颜色分段解析接收一个对象，仅当对象为字符串、字段数为四、所有字段可解析且范围正确时返回四个整数。
- 默认颜色解析接收一个对象，仅当对象为字符串、字段数为三、所有字段可解析且 RGB 范围正确时返回三个整数。
- 解析失败以空结果表示，不抛出异常。

两个 Forge 配置校验器通过解析结果是否存在判断合法性。`getColorSegments` 再次调用颜色分段解析器，仅缓存合法结果并按难度升序排列。`getDefaultColor` 调用默认颜色解析器；失败时使用固定灰色回退值。

字段使用逗号精确拆分并允许字段两侧存在空白。空字段、多余字段、负号、非数字、超出 `int` 范围的难度及超出 `0–255` 的通道均为非法。难度 `0`、难度 `2147483647`、通道 `0` 和通道 `255` 均为合法边界。

配置注释明确写出 RGB 的有效范围为 `0–255`，避免用户误以为任意非负整数都可用。

## 错误处理

- Forge 正常加载配置时，严格校验器会拒绝非法条目并交由配置系统执行现有纠正流程。
- 若值通过程序化方式进入运行时或绕过配置纠正，运行时解析仍不会把非法通道交给颜色打包函数。
- 单个非法分段不会导致整张分段表失效。
- 默认颜色非法时始终回退为不透明 `RGB(170,170,170)`。

## 验证

自动测试覆盖：

- 合法分段与默认颜色。
- 难度边界 `0` 和 `2147483647`。
- RGB 边界 `0` 和 `255`。
- RGB `256`、负数与非数字。
- 难度整数溢出。
- 字段不足、字段过多与空字段。
- 字段两侧空白。
- 合法和非法分段混合时仅保留合法分段。
- 非法默认颜色回退为 `RGB(170,170,170)`。
- 现有缓存失效测试继续通过。
