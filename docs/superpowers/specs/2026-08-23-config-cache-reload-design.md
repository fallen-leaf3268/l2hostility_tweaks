# 配置缓存重载设计

## 目标

Forge 在运行中重载 `l2hostility_tweaks` 配置后，使所有由配置列表解析得到的缓存于下一次读取时重新构建，不要求玩家重启客户端或服务器，并保持现有默认值、解析规则和游戏行为不变。

## 已确认问题

`L2HConfig` 缓存等级阈值、逐词条阈值、传奇阈值、额外传奇 ID、互斥组、封印持续时间数组和玩家词条覆盖；`ClientL2HConfig` 缓存 HUD 颜色分段。项目没有监听 `ModConfigEvent.Reloading`。已有的 `invalidatePlayerTraitOverrides()` 只覆盖一个缓存且没有调用方。因此 Forge 配置值虽然已经更新，缓存型 getter 仍返回首次解析的旧对象。

## 设计

### 缓存所有权

`L2HConfig` 提供一个统一的缓存失效方法，一次将其七个解析缓存置空。`ClientL2HConfig` 提供独立失效方法，只清除 HUD 颜色分段缓存。缓存引用使用 `volatile`，确保配置事件线程清除后，后续游戏或渲染线程能够观察到变化；允许极少量并发重复解析，因为结果等价且不会修改配置。

### 事件路由

`L2HostilityFix` 在模组事件总线上监听 `ModConfigEvent.Reloading`。事件处理按配置规范对象区分来源：

- `L2HConfig.SPEC` 重载时，只清除通用配置缓存。
- `ClientL2HConfig.CLIENT_SPEC` 重载时，只清除客户端颜色缓存。
- 其他模组或其他配置规范的事件不处理。

初次加载不需要主动清理，因为所有缓存初始均为空。事件处理不重新解析数据；下一次正常 getter 调用按最新配置惰性重建。

## 兼容性与错误处理

不取消缓存，不在 HUD 每帧重新解析列表，也不改变 Forge 的配置文件监听方式。无效配置仍由现有 Forge 校验和各解析器处理。本设计不自动写回 TOML，不增加日志，不触碰原版或其他模组配置。

## 测试

- 验证通用缓存失效方法会清除全部七个缓存，而不只清除玩家覆盖缓存。
- 验证客户端缓存失效后，颜色分段会在下次读取时重建。
- 验证事件路由只使匹配的配置规范失效。
- 执行定向测试和完整 `clean build`，确认资源校验、Mixin 编译和全部现有测试通过。
- 生成 JAR 但不部署到 `mods`。
