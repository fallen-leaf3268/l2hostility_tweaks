# 词条文本像素折行设计

## 背景

目标 HUD 与玩家词条面板分别维护了一份相同的词条排版逻辑。当前逻辑在本行为空且首个词条已经超过可用宽度时，仍会把空行加入结果。目标 HUD 因此产生额外的垂直间隔；玩家词条面板还会让空行占用每页十行的分页额度。随后加入的超宽词条依然会越过右边界。

HUD 的词条区域随 `hudBarWidth` 变化，可用宽度为血条宽度减去边距；玩家词条面板的词条区域固定为 160 像素。修复必须同时覆盖两个界面。

## 目标

- 任何输入都不生成空排版行。
- 每个渲染片段的实际字体宽度不超过对应界面的可用宽度。
- 普通词条仍尽量按现有规则排列在同一行，并以两个空格分隔。
- 超宽词条按 Minecraft 当前字体的实际像素宽度折成多个片段。
- 保留翻译后文本的颜色、删除线及其他样式。
- 玩家面板中，超宽词条的每个片段均保留原词条归属，支持悬停提示和右键卸载。
- HUD 与玩家面板共享同一套排版规则。

## 非目标

- 不改变词条名称、等级文本或本地化内容。
- 不缩放、截断或省略词条文本。
- 不改变 HUD 血条宽度配置、玩家面板尺寸或每页行数。
- 不改变悬停提示内容、卸载规则或网络协议。

## 设计

新增一个客户端内部使用的词条文本排版组件。组件接收有序词条、最大像素宽度和字体适配器，输出有序的排版行。每个输出片段包含渲染文本、所属词条、横向偏移和实测宽度。

排版顺序如下：

1. 使用当前字体测量完整词条。
2. 若完整词条能放入当前行，则按现有双空格间隔加入。
3. 若当前行非空且剩余宽度不足，先结束当前行，再处理该词条。
4. 若词条本身不超过最大宽度，将其加入新的当前行。
5. 若词条本身仍然超宽，使用 Minecraft 的样式感知文本拆分能力生成多个片段；每个片段独占一行，并继承同一个词条归属。
6. 仅在行实际含有片段时才加入结果。

分隔符只存在于同一行的两个完整词条之间，不出现在新行开头，也不插入超宽词条的连续片段之间。

## 界面接入

### 目标 HUD

HUD 在刷新词条缓存时调用共享排版组件，缓存排版后的样式文本片段。渲染阶段按片段横向偏移绘制，不再自行执行换行判断。HUD 不需要使用片段的词条归属，但保留统一的数据结构。

### 玩家词条面板

玩家面板使用同一排版结果进行绘制、分页、悬停命中和右键命中。超宽词条的每个片段都携带相同词条引用，因此用户在任意一段上操作都得到与未折行词条相同的行为。分页仍以实际渲染行计数。

## 边界与容错

- 最大宽度至少按 1 像素处理，避免非法宽度造成无限拆分或空结果。
- 字体拆分若返回空片段，则忽略空片段；不得生成空行。
- 宽度恰好等于上限时不折行。
- 词条输入顺序保持不变。
- 封印词条的灰色删除线样式在所有拆分片段上保持一致。

## 验证

自动测试覆盖：

- 多个普通词条在同一行排列。
- 加入分隔符后恰好达到宽度上限。
- 新词条放不下时正常换行且没有空行。
- 第一条词条即超宽时拆成多段且没有前置空行。
- 普通词条后接超宽词条时，顺序、片段归属和偏移正确。
- 每个输出片段宽度不超过最大值。
- 超宽封印词条的样式在拆分后保留。
- 玩家面板的每个折行片段均可命中原词条。

最后运行完整测试与干净构建，检查生成 JAR，并确认未将 JAR 部署到 `mods` 目录。
