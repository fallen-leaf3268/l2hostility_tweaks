# NBT 预设词条 ID 安全解析设计

## 目标

让 NBT 实体配置中的单个非法预设词条 ID 只影响自身，不再中断它后面的合法预设词条，同时保持合法预设的等级和初始化行为不变。

## 已确认根因

`TraitGeneratorMixin` 在遍历 NBT 预设时通过 `new ResourceLocation(traitId)` 直接解析数据包输入。格式错误会抛出 `ResourceLocationException`，而该异常只由整个预设处理流程最外层的 `catch` 捕获，因此当前循环立即终止。

反射读取错误已经按单条捕获，合法但未注册的词条也已经按单条警告并继续；只有资源 ID 格式错误仍能越过单条边界，造成处理结果依赖配置顺序。

## 设计

在 `TraitGeneratorMixin` 中增加一个包可见的静态解析方法：

```java
static ResourceLocation l2fix$parseTraitId(String traitId)
```

该方法使用 `ResourceLocation.tryParse`，对合法 ID 返回解析结果，对非法或空输入返回 `null`，不抛出格式异常。

预设循环在注册表查询前调用该方法：

- 返回 `null` 时，记录包含原始 ID 的警告并继续下一条预设。
- 返回合法资源位置时，查询词条注册表。
- 合法但未注册的 ID 继续沿用现有警告并跳过逻辑。
- 找到词条后，继续使用现有的等级比较、写入、`initialize` 和计数逻辑。

最外层异常保护继续保留，用于防御注册表、能力或反射之外的未知异常，但资源 ID 格式错误不再依赖该总兜底。

## 数据流

数据包预设字符串先经过安全解析，再进入词条注册表。每个预设条目独立完成“读取字段、解析 ID、查询注册表、比较等级、应用词条”；任一步骤失败时只跳过当前条目，后续条目继续处理。

## 错误处理

格式非法与未注册是两种不同日志：

- 格式非法：说明 ID 无法解析，并输出原始字符串。
- 未注册：保留现有“注册表中不存在”的警告。

两者均不抛出异常、不应用错误词条，也不阻止后续合法预设。

## 测试

扩展现有 `TraitGeneratorMixinTest`：

1. 合法 ID `l2hostility:tank` 能被解析。
2. 含空格的非法 ID 返回 `null`，且不抛异常。
3. `null` 输入返回 `null`。
4. 静态检查确认循环中不再存在 `new ResourceLocation(traitId)`。
5. 完整运行 `clean build`，确认全部单元测试、资源校验和 JAR 构建通过。

## 非目标

- 不修改预设等级覆盖规则。
- 不改变合法但未注册词条的处理方式。
- 不调整 NBT 匹配条件、配置合并或反射字段发现逻辑。
- 不新增配置项或运行时依赖。
- 不将 JAR 部署到 `mods`。
