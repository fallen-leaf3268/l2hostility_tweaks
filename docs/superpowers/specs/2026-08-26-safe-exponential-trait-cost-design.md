# 安全指数词条费用设计

## 目标

修复玩家词条费用模式 3 使用 `int` 左移导致的负费用、周期回绕、异常退款和非法物品堆，同时保持默认等级范围内的升级与卸载经济不变。

## 范围

- 统一客户端费用提示、服务端升级扣费、单级卸载退款和全部卸载退款的指数费用计算。
- 指数模式以词条符文实际最大堆叠数作为单次支付上限。
- 普通模式和线性模式的现有数值规则不变。
- 不增加跨背包多堆材料支付，不改变词条等级上限，不部署 JAR 到 `mods`。

## 费用规则

指数模式在当前等级 `L` 升至 `L + 1` 时，理论费用为 `2^L`。

- 当理论费用不超过符文最大堆叠数时，返回准确费用。
- 当理论费用超过最大堆叠数或等级无法安全参与计算时，标记为不可支付。
- 客户端对不可支付状态显示专用提示，不显示负数或回绕后的错误数字。
- 服务端以同一结果拒绝升级，不能仅依赖客户端。

默认最大堆叠数 64 时，等级 0 至 6 的升级费用依次为 1、2、4、8、16、32、64；从等级 7 开始不可通过当前单堆支付流程继续升级。

## 退款规则

单级卸载只返还该等级对应的、曾可合法支付的费用。超过可支付阶段的高等级按最后一个合法阶段的费用封顶，因此默认最大堆叠数 64 时单级最多返还 64。

全部卸载返还所有合法支付阶段的累计值。默认最大堆叠数 64 时，指数模式最多返还：

`1 + 2 + 4 + 8 + 16 + 32 + 64 = 127`

退款必须拆分成不超过物品最大堆叠数的多个 `ItemStack`，依次尝试放入玩家背包，剩余部分掉落，不能创建数量为负、零或超出堆叠上限的物品堆。

## 结构

新增独立的纯计算工具，接受费用模式、等级和最大堆叠数，提供：

- 下一等级升级费用及是否可支付；
- 单级卸载退款；
- 全部卸载退款。

`PlayerTraitScreen`、`TraitSymbolSelfUseMixin`、`L2HConfig` 和 `TraitUnloaderWand` 通过该工具获得相同结果。`TraitWandHelper` 负责将退款总数拆分并安全交付，不负责决定经济数值。

## 异常输入

- 非正最大堆叠数视为不可支付且退款为零。
- 非正等级的退款为零。
- 负的当前升级等级视为不可支付。
- 计算过程中使用 `long` 或边界比较，禁止依赖可能溢出的 `int` 位移。

## 测试

- 验证默认堆叠上限下 0 至 6 级费用准确，7、31、32 级均不可支付。
- 验证 31、32 级不会产生负数、回绕费用或异常巨额退款。
- 验证单级退款封顶 64，全部退款封顶 127。
- 验证退款拆分为 64 和 63，且每个物品堆均合法。
- 验证客户端和服务端调用统一计算工具，不保留直接 `1 << level` 的运行时代码。
- 运行完整 `clean test check build` 并检查最终 JAR 内容与输出哈希。
