# 玩家词条面板卸载修复设计

## 问题

`PlayerTraitScreen` 右键词条后会发送 `UnloadTraitPacket`。提交 `2c8d77e` 在服务端处理该包时新增了“主手必须持有 `TraitUnloaderWand`”的条件；面板本身不要求玩家持有该测试工具，因此合法卸载请求被静默拒绝。

## 目标

- 玩家通过词条面板右键卸载一级词条，Shift+右键卸载整组词条时，不需要持有词条卸载工具。
- 词条卸载工具继续保留，作为测试入口使用。
- 不改变卸载费用、退款数量、封印清理和词条能力同步。

## 方案

移除 `UnloadTraitPacket` 中对玩家主手物品的限制。保留服务端现有校验：发送者必须存在、玩家必须具有词条能力、能力必须初始化、词条 ID 必须合法且已注册、玩家必须实际拥有该词条且等级非零。最终卸载和退款仍完全依据服务端能力数据计算，不信任客户端提供等级或退款数量。

## 测试

将现有锁定错误行为的测试改为验证卸载包不依赖 `TraitUnloaderWand`，同时验证词条能力、合法 ID、实际持有等级检查均发生在卸载调用前。先运行该测试确认其在现状下失败，再删除错误条件并确认测试通过，最后运行完整测试、资源校验与重混淆 JAR 构建。
