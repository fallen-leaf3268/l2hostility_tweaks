# 分裂抑制目标选择修复设计

## 问题

当前 `RemoveTraitEnchantmentMixin` 在目标没有分裂词条时，会回退选择第一个有效词条并永久封印。该行为与附魔名称、Tooltip“永久封印目标分裂词条”以及上游附魔固定操作分裂词条的语义不一致。

## 设计

分裂抑制只查找 ID 为 `l2hostility:split` 且原始等级大于 0 的词条：

- 存在有效分裂词条时，取消上游删除逻辑并沿用现有永久封印流程；
- 分裂词条不存在、等级为零或已经是负等级封印状态时，不选择其他词条，不写入封印数据；
- 不新增配置，不修改 Tooltip，不调整其他封印来源。

将目标选择提取为包内可测试的纯方法，输入词条等级映射，输出待封印词条或空值。Mixin 的实际处理只消费该选择结果。

## 验证

新增回归测试覆盖：

1. 没有分裂词条时，即使存在其他有效词条也返回空值；
2. 有正等级分裂词条时只返回分裂；
3. 分裂词条已经封印时返回空值，不回退到其他词条。

最后运行完整 `clean build`，并把构建产物复制到统一输出目录，不部署到 `mods`。
