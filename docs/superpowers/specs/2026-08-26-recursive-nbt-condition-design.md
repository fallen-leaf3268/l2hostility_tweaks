# 递归 NBT 条件匹配设计

## 目标

修复实体配置中的嵌套对象、数组、小数和长整数被丢弃或失真的问题，并保证任何空条件或无效条件都不会退化为无条件实体配置。

## 根因

`ConfigMergerMixin` 当前把 JSON `nbt` 对象转换成 `Map<String, Object>`，且只保留顶层布尔、数字和字符串。对象与数组会被静默忽略，数字统一通过 `getAsInt()` 转换。若一个条件只包含嵌套数据，转换结果为空，后续 `EntityConfigMixin` 会把该条目当成普通配置，导致原本受 NBT 限制的配置可能作用于所有同类型实体。

## 数据表示

NBT 条件以 Gson 的 `JsonObject` 原样保留，不转换为 Java 基础类型 Map，也不预先转换为 Minecraft `Tag`。这样可以保留完整树结构、JSON 数字文本和配置来源信息，避免小数截断与 64 位整数溢出。

新增一个由 `EntityConfigConfigMixin` 实现的显式数据接口，配置合并与分类代码通过接口读写条件，不再反射查找 Mixin 注入字段。接口保存条件状态、有效条件树以及诊断来源。条件状态使用 `NONE`、`VALID`、`INVALID` 三态，避免用 null 或空 Map 同时表达多个含义。

每条读取到的 `nbt` 条目必须处于以下三种明确状态之一：

- 不存在 `nbt` 字段：普通实体配置。
- 存在且有效的非空 `nbt` 对象：NBT 条件配置。
- 存在但为空或无效：禁用该条配置并记录警告，不得进入普通缓存或条件列表。

## 匹配语义

递归匹配器接收一个 JSON 条件节点和一个 Minecraft NBT 节点：

- 对象对应 `CompoundTag`。只检查配置中声明的键，实体可包含额外键，因此对象采用递归部分匹配。
- 数组对应 `ListTag`。长度、顺序和每个元素都必须匹配。
- 布尔值只匹配数值为 `0` 或 `1` 的 `ByteTag`。
- 字符串与 NBT 字符串内容精确匹配。
- JSON 数字按任意精度十进制解析。byte、short、int、long 标签以精确整数转换；float 使用 `Float.toString()` 的规范十进制表示；double 使用 `BigDecimal.valueOf()` 的规范十进制表示，然后进行数值比较。这样 `0.1` 可匹配保存为 `0.1f` 的值，同时不会因 float 精度把相邻的大整数误判为相等。
- JSON null 不作为“键不存在”语法，视为无效条件。
- 嵌套空对象 `{}` 是合法条件，表示对应键必须存在且为复合标签；顶层空 `nbt` 对象无筛选意义，视为无效配置。

数值比较以规范十进制数值相等为准，不要求 NBT 的 byte、short、int、long、float、double 标签类型与 JSON 推断类型相同。实际 float/double 为非有限值时不匹配。

## 合并与失效处理

`ConfigMergerMixin` 在读取资源时为每个配置条目保存完整条件及其有效状态。资源 ID 和条目索引用于诊断信息。它通过显式接口写入三态元数据，并删除原有的反射字段发现与读写缓存。

`EntityConfigMixin` 在 `postMerge` 尾部完成分类：

- 有效条件条目从普通实体缓存移除，并登记到 `l2hostility_tweaks:nbt` 条件列表。
- 无 `nbt` 的条目保持原版普通配置行为。
- 空或无效条件条目从普通实体缓存移除，且不登记为条件配置。

解析或验证失败必须输出一次警告，包含资源 ID、条目索引和原因。单条错误不得中断其他资源或条目的加载。

## 兼容性

现有顶层布尔、字符串和整数配置保持原有含义。现有合法的小数配置从截断行为修正为准确数值匹配。配置格式仍使用 JSON 对象，不引入 SNBT 字符串或新的用户配置字段。

条件优先级继续沿用合并后的条目顺序，不改变普通实体配置与有效 NBT 条件配置之间现有的选择顺序。

## 测试

自动测试至少覆盖：

- 嵌套复合标签部分匹配并允许额外字段。
- 缺少嵌套键或值不同时拒绝匹配。
- 列表长度、顺序或元素不同时拒绝匹配。
- 布尔与 ByteTag `0/1` 的匹配边界。
- 小数不再被截断。
- long 最大值附近的整数保持精确且不溢出。
- JSON null、非法数字和非有限实际数值安全失败。
- 条件元数据通过显式接口传递，不再依赖反射字段。
- 顶层空对象和无效条件不会进入普通实体缓存。
- 合法扁平条件继续工作，多个配置条目相互隔离。
