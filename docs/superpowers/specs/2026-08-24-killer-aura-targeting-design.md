# 杀戮光环目标选择修复设计

## 目标

修复玩家持有杀戮光环时自身进入伤害流程的问题，并把当前分散且部分失效的目标判断合并到实际执行伤害的 `KillerAuraTraitMixin` 中。

## 已确认根因

`KillerAuraTraitMixin` 在 `tick` 方法开头取消原实现，然后在注入处理器内重新查询范围实体。新循环把所有非创造玩家视为候选目标，却没有排除光环持有者，因此非创造玩家持有该词条时会把自己传入 `hurt(...)`。

`KillerAuraSelfMixin` 的 Redirect 只修改原 `tick` 方法中的调用。原方法已被另一 Mixin 取消，且新循环位于注入处理器方法中，所以这些 Redirect 无法过滤替代循环，也无法补充“玩家最近攻击过该生物”的判断。该 Mixin 还用静态 `ThreadLocal` 保存持有者且从不清除。

## 目标选择规则

`KillerAuraTraitMixin` 统一计算候选实体与持有者的关系，再交给一个纯布尔决策方法：

1. 候选实体就是持有者本人时，始终拒绝，优先级高于所有其他关系。
2. 其他非创造玩家继续作为目标，保持现有范围攻击行为。
3. 候选生物当前以持有者为目标时，作为目标。
4. 持有者是生物且其当前目标是候选实体时，作为目标。
5. 持有者是玩家、候选生物最近被该玩家攻击过时，作为目标，恢复旧 Redirect 想表达的行为。
6. 以上关系全部不满足时，不攻击候选实体。

现有距离检查、阿布拉卡达布拉保护、词条受击事件、伤害类型、伤害数值、攻击间隔、范围和客户端粒子保持不变。

## 实现结构

在 `KillerAuraTraitMixin` 中增加包可见静态决策方法，参数分别表示：是否自身、是否其他非创造玩家、候选是否以持有者为目标、持有者是否以候选为目标、候选是否最近被玩家持有者攻击。方法只组合布尔值，不访问世界或实体状态，便于完整单测。

伤害循环负责从真实实体计算这些布尔值，并在决策方法返回 `false` 时跳过。自身判断在关系计算结果中传入，因此即使异常状态下实体把自己设为目标，也不会绕过自身排除。

删除 `KillerAuraSelfMixin.java`，并从 `l2hostility_tweaks.mixins.json` 移除对应注册。这样不再保留失效 Redirect 或静态 `ThreadLocal`。现有资源校验任务会保证 Mixin 源文件和注册表继续一一对应。

## 测试

新增 `KillerAuraTraitMixinTest` 覆盖目标决策：

1. 自身即使同时满足其他全部关系也必须拒绝。
2. 其他非创造玩家被接受。
3. 候选以持有者为目标时被接受。
4. 生物持有者以候选为目标时被接受。
5. 候选最近被玩家持有者攻击时被接受。
6. 没有任何敌对关系时被拒绝。

资源校验继续确认删除的 Mixin 不再注册且没有未注册的残留源文件。最后执行完整 `clean build` 并输出 JAR。

## 非目标

- 不改变杀戮光环对其他玩家的现有 PvP 规则。
- 不改变创造模式判断之外的无敌或伤害免疫规则。
- 不调整杀戮光环伤害、间隔、范围或粒子。
- 不修改其他传奇词条。
- 不把 JAR 部署到 `mods` 目录。
